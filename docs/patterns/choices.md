# Choice Patterns

Magic::Choice subclasses — targeting, modal, may, search, scry, distribute, copy-spell, redirect. Part of the card-implementation pattern catalog — see `docs/card_patterns.md` for the index.

**Targeted ETB trigger ("deals damage to any target")**: Add `Magic::Choice::Targeted` subclass to card's class reopening. Define `choices` (e.g. `game.any_target`) and `resolve!(target:)`. In trigger's `call`, push instance onto `game.choices`. Pass data needed at resolution (e.g. entering creature's power) via constructor. Example: `TerrorOfThePeaks::DamageChoice`.

**Modal ETB choice (pick one of N effects)**: Subclass `Magic::Choice` directly. Define `resolve!(mode:)` with a `case mode` switch. Use symbol constants (e.g. `COUNTER = :counter`). In the ETB trigger's `call`, push an instance onto `game.choices`. Example: `Trufflesnout`.

**Optional ETB (may do X)**: Wrap the real choice in a `Magic::Choice::May` subclass — override `resolve!` to push the inner choice onto `game.choices`. Example: `AlpineHoundmaster::MaySearchChoice`.

**Library search with specific card filter**: Subclass `Magic::Choice::SearchLibrary` and override `choices` to return a filtered `CardList` (e.g. `controller.library.by_name("Alpine Watchdog")`). Pass `upto:`, `reveal:` to `super`. Example: `AlpineHoundmaster::SearchChoice`.

**Targeting artifacts/enchantments**: Use `game.battlefield.by_any_type("Artifact", "Enchantment")` — string type names work alongside `T::` constants.

**Aura target restriction**: Override `target_choices` on the Aura card class to restrict which permanents can be targeted. Example: `SetessanTraining` restricts to `battlefield.controlled_by(controller).creatures`.

**Scry then reveal top card (conditional draw)**: Subclass `Magic::Choice::Scry`, call `super(**args)` to perform the scry, then inspect `controller.library.first` and fire `game.notify!(Events::CardsRevealed.new(cards: [top_card]))` directly (no Effect needed — `notify!` is the right tool for a plain reveal). Check `top_card.creature? || top_card.land?` — these methods work on Card objects via `lib/magic/types.rb`. Example: `TrackDown::ScryChoice`.

**"As ~ enters, choose a creature type"** (e.g. banners/tribal lands): No shared "choose type" infra beyond a bare `Magic::Choice::CreatureType < Magic::Choice` (mirrors `Magic::Choice::Color`, lives at `lib/magic/choice/creature_type.rb`). `chosen_creature_type` is a generic `attr_accessor` on `Magic::Permanent` itself (`lib/magic/permanent.rb`) — push a card-specific `CreatureTypeChoice` subclass (`resolve!(creature_type:)` sets `actor.chosen_creature_type = creature_type`) from an `EnterTheBattlefield` trigger; later abilities read it via `source.chosen_creature_type`. This works directly on the permanent (no `.card` indirection needed) because `actor`/`source` inside trigger and static-ability instances is always the same long-lived `Permanent` object for as long as the card stays on the battlefield. Example: `PatchworkBanner`, `ThreeTreeCity`, `VanquishersBanner`. (Older cards like `UtopiaSprawl` still route a similar `chosen_color` through `Card`'s own pre-existing `attr_accessor :chosen_color` via `actor.card.chosen_color` — both approaches exist in the codebase; prefer storing directly on the `Permanent` for new "chosen X" state unless matching an existing sibling card's convention.)

**"Choose a color other than black" (or similar restricted color choice)**: Subclass `Magic::Choice::Color`, define the allowed list as a `COLORS` constant on the subclass and validate inside `resolve!(color:)` (`raise` if not included) — there's no shared enforcement of the restriction elsewhere in the choice/target pipeline. Example: `ThrivingMoor`, `UtopiaSprawl`.

**"Do X, then Y; if you can't, do Z instead" (fallback when a choice has no valid targets)**: Don't rely on `Stack#add_choice`'s auto-resolve (it only fires when there's exactly *one* valid choice, not zero). Instead, build the choice object first, check `choice.choices.any?` yourself, and only `game.choices.add(choice)` when there's at least one option — otherwise trigger the fallback effect directly. Example: `RootsOfWisdom` (mills 3, returns a land-or-Elf card from the graveyard via a `Magic::Choice::SearchGraveyard` subclass, or draws a card if none exists).

**"You may pay {X}{X}. When you do, [effect] distributed/scaled by X"**: There's no built-in "optional variable mana cost paid mid-trigger" cost type — implement it as a `Magic::Choice::May` subclass whose `resolve!(x:, payment: {})` calls `controller.pay_mana(payment)` directly (a plain color-hash payment, not a `Costs::Mana` object — this is a trigger resolving, not a cast/activation going through the normal cost-payment pipeline) and, only then, pushes the follow-up effect/choice; declining is just `game.skip_choice!`. For "distribute N counters among any number of targets," a plain `Magic::Choice` subclass takes an `amount:` in its constructor, exposes the valid target list via `choices`, and resolves with a `resolve!(distribution:)` taking a `{permanent => count}` hash (nothing validates the counts sum to `amount` — trust the caller, matching this codebase's general looseness around cost/payment validation). Example: `NumaJoragaChieftain`.

**Modal spells ("Choose one —" / "Choose one or more —")**: There's a full, working, but easy-to-miss modal system: subclass `Magic::Cards::Mode` (`lib/magic/cards/mode.rb`, `source`/`controller`/`trigger_effect` all delegate to the card) once per mode, each with its own `target_choices`/`resolve!(target:)` (or a no-target `resolve!` for a mode with no target), then declare `modes Mode1, Mode2, ...` on the card. The card class itself is written as a raw `class CardName < Sorcery; card_name "..."; cost ...; end` (**not** the `Sorcery("Name") do ... end` block form) — `card_name`/`cost` are plain class-body DSL calls. At cast time, `action.choose_mode(SomeMode) { |mode| mode.targeting(target) }` — call it once per chosen mode; nothing enforces "choose one" vs "choose one or more" vs "not the same mode twice", so a "choose one" charm's spec just calls `choose_mode` once and a "choose one or more" spell's spec calls it multiple times. Examples: `RakdosCharm` ("choose one"), `SublimeEpiphany` (up to five modes at once), `CasualtiesOfWar` (all five destroy modes).

**"That player sacrifices a [filtered] creature of their choice" (edict targeting whoever the trigger names, not the source's controller)**: `Magic::Choice`'s default `controller = actor.controller` assumes the chooser is the source's controller — wrong here, since `event.player` (the affected upkeep's player) can be either player. Pass that player into the choice explicitly (`SacrificeChoice.new(actor: actor, player: event.player)`, stored as its own ivar, not read via `controller`) and build `choices` off it (e.g. `@player.creatures.excluding_type("Elf")`). Subclass `Magic::Choice::Targeted` with `choice_amount 1` and `resolve!(target:) = target.sacrifice!` (mirrors `Effects::Sacrifice`/`GodEternalBontu`, called directly rather than via `trigger_effect` since the choice already carries the target). Since this is mandatory (not `Choice::May`), only call `game.choices.add(choice)` when `choice.choices.any?` — the "do X, then Y; if you can't" fallback pattern applies even with no explicit "if you can't" clause: an empty pool just means nothing happens, so guard the `add` rather than pushing a choice with no valid targets. Example: `RuthlessWinnower`.

**A `Magic::Choice::Targeted` with exactly one legal target resolves itself immediately** — `Stack#add_choice` checks `choice.single_target? && choice.single_choice?` (i.e. `target_choices.count == 1`) and calls `resolve_choice!` right away instead of queuing it, so `game.choices` stays empty and a spec expecting to see the choice and drive it with a separate `game.resolve_choice!(target: ...)` call will find nothing there. This is different from the "if you can't" empty-pool guard (zero targets — don't call `add_choice` at all) covered elsewhere in this file; this is the *one*-target case, and it's the choice-adding code itself that special-cases it, not something a card needs to guard against. Give a test scenario at least two legal targets if it needs to assert the choice is actually pending and manually resolved; with only one, just assert the outcome directly. Example: `FieryInscription` (a controller with a single creature becomes the Ring-bearer with no separate `resolve_choice!` call). **This auto-resolve only fires through `game.add_choice(choice)`** (`Game`'s delegator to `Stack#add_choice`) — the more commonly-seen `game.choices.add(choice)` calls straight into `Stack::Choices` (a bare `SimpleDelegator#unshift`, no special-casing), so a mandatory single-target trigger written that way always queues the choice, even with exactly one legal target. Use `game.add_choice(...)` when the auto-resolve behavior matters to the card's own test coverage. Example: `LivaanCultistOfTiamat`.

**"Reveal the top N cards" into a custom multi-part choice** (not a straight search/scry): wrap `actor.controller.library.first(n)` in `Magic::CardList.new(...)` — `Zone#first` (via `Enumerable`) returns a plain `Array`, so you lose `.lands`/`.by_any_type` filtering unless you rewrap it. Reveal with `controller.reveal(*cards)`. To return the unchosen cards "to the bottom in a random order", each card is still physically present in the library's items (only cards actually moved via `move_to_hand!`/`resolve!` are removed) — `remove` then `push` each one, don't just `push`, or they'll be duplicated. Example: `BountyOfSkemfar`.

**"Choose one that hasn't been chosen this turn" (Alliance and similar repeatable modal triggers)**: `Magic::Permanent` has a generic `modes_chosen_this_turn` tracker — `mode_chosen_this_turn?(mode)` / `choose_mode_this_turn!(mode)` — reset in `cleanup!` (so it naturally expires at the end of the turn it was set, same timing as `until_eot` modifiers; reaching cleanup in a spec requires driving the turn state machine all the way there, e.g. `current_turn.untap!; ...; current_turn.cleanup!`, not `game.next_turn`, which just creates a fresh `Turn` object without running the previous turn's `cleanup` step). A plain `Magic::Choice` subclass filters its own `choices` list with `MODES.reject { |mode| actor.mode_chosen_this_turn?(mode) }` and calls `actor.choose_mode_this_turn!(mode)` inside `resolve!`; only push the choice when `choice.choices.any?` (same empty-pool guard as the "if you can't" pattern). Example: `GalaGreeters`.

**"Put any number of land cards from your hand onto the battlefield tapped" (optional variable-count zone change)**: Subclass `Magic::Choice::MoveToBattlefield` (`lib/magic/choice/move_to_battlefield.rb`) — its `choices` method returns a `Magic::Targets::Choices.new(amount: 0..n, choices: ...)` (an inclusive range starting at 0 covers "any number, including none"; `n` should be computed live off the current zone, e.g. `hand.lands.count`, not cached), and `resolve!(choices:)` calls `.resolve!` on each chosen card — override `resolve!` to pass `enters_tapped: true` when the effect requires it (the base class's `resolve!` doesn't). Always `game.choices.add(...)` unconditionally here rather than guarding on "any left" — `0..0` for an empty pool is itself a valid "choose zero" choice. Drive it in specs with `game.resolve_choice!(choices: [...])`. Example: `UginTheSpiritDragon` (permanents, no tapped requirement), `WrennAndSeven` (0 ability, lands only, tapped).

**"You may choose new targets for target spell or ability"** (redirect effect): `target_choices` for the redirect spell itself is `(game.stack.spells + game.stack.abilities).select { |item| item.respond_to?(:targeting) && item.targets.any? }` — `game.stack.abilities` also returns `TriggeredAbility` instances, which have no `targets`/`targeting` (they resolve targets via pushed `Choice` objects, not a stored `targets` list), so the `respond_to?(:targeting)` guard naturally limits this to `Actions::Cast` and `Actions::ActivateAbility` items; retargeting a triggered ability isn't supported by this mechanism. Wrap the actual retarget in the two-step "may" pattern (`Choice::May` pushing a `Choice::Targeted` — same shape as `NecroblossomSnarl`): the inner choice's `choices` is the targeted item's own legal-target list (`item.card.target_choices` for a spell — mind the 0/1-arity check `Actions::Cast#target_choices` itself does, `item.ability.target_choices` for an activated ability), and `resolve!(target:)` just calls `item.targeting(target)`, which re-validates against the item's current `target_choices` and replaces its `@targets` outright (fine for single-target spells/abilities; a multi-target one would lose its other targets). Example: `DeflectingSwat`.

**"Copy target instant or sorcery spell. You may choose new targets for the copy."** (or any other "copy that spell/ability" wording): No copy-spell mechanism existed. `Magic::CopyEffect` (`lib/magic/copy_effect.rb`) is the generic core — `.resolve!(receiver, targets:)` calls `receiver.resolve!` directly with the filtered kwargs it actually declares (same `resolve_with_args`-style filtering `Actions::Cast`/`Actions::ActivateAbility` already do), reproducing a spell's or ability's effect with **no** stack entry and **no** zone change — a copy isn't a real card/object, so this bypasses `Actions::Cast` entirely rather than re-adding the copy to the stack. `receiver` is whatever the *card's own* `resolve!` is defined on: `target.card` for a targeted `Actions::Cast` picked up off `game.stack.spells`, or `event.spell`/`event.ability` directly off a `SpellCast`/`AbilityActivated` event (no `Actions::Cast` object needed there at all). `.resolve_with_choice!(actor:, receiver:, targets:, copies: 1)` is the "you may choose new targets" wrapper: with no targets to begin with it just resolves `copies` copies immediately; otherwise it pushes `Magic::Choice::MayCopyTargets` (`lib/magic/choice/may_copy_targets.rb`) — accepting queues `Magic::Choice::CopyTargets` (`lib/magic/choice/copy_targets.rb`, target list from `receiver.target_choices`, `resolve!(target:)` runs `copies` copies against the one chosen target), declining runs `copies` copies against the *original* targets via its `decline!` override (the default `Choice::May#decline!` is a no-op, so this is the one place that matters). Drive it in specs exactly like `DeflectingSwat`'s two-step retarget choice: `game.resolve_choice!` (accept) then `game.resolve_choice!(target: ...)` (pick), or `game.skip_choice!` (decline, applies immediately since `decline!` isn't queued). Since `Actions::Cast#perform` only pushes onto the stack, `target.card.resolve!` for a copy targeting something still on the stack only fires once you call `game.stack.resolve!` — the copy is created and resolves *while the copying spell resolves*, before the original spell underneath it gets its turn. Example: `Reiterate` (single copy, target chosen from `game.stack.spells`).

**Storm** ("Copy this spell for each spell cast before it this turn. You may choose new targets for the copies."): No dedicated storm mechanic — `Game::Turn#spells_cast` (all `Events::SpellCast` this turn, already tracked before listeners run) is enough on its own: inside the spell's own `resolve!`, `game.current_turn.spells_cast.count - 1` is the number of spells cast *before* this one (subtracting the storming spell's own cast event, which was already recorded when it was cast). Compute this at resolution, not via an `event_handlers`/`SpellCast`-trigger hook — the card isn't subscribed to game events while sitting in hand (only graveyard/exile/command zones subscribe cards), so there's no cast-time hook to catch its own cast anyway, and resolution time is when real storm's copies actually go on the stack. **Never pass `self` as `Magic::CopyEffect`'s `receiver`** for the storm copies — `CopyEffect.resolve!` calls `receiver.resolve!(target:)` directly, so a self-referencing receiver would recursively recompute storm count and resolve *its own* copies again, compounding exponentially instead of linearly. Split the actual one-shot effect into its own public method (e.g. `deal_damage(target:)`) and route the copies through a tiny local receiver object that forwards `target_choices`/`resolve!(target:)` to that method instead of to the card's real `resolve!`. Reuse `Magic::CopyEffect.resolve_with_choice!(actor: self, receiver: Copy.new(source: self), targets: [target], copies: storm_count)` for the "you may choose new targets" part — one `MayCopyTargets` choice governs all copies at once (a single accept/decline, not one choice per copy), matching how a 1-copy card like `Reiterate` already behaves. Example: `Grapeshot`.

**A pending choice blocks ALL stack resolution, not just the item that spawned it**: `Stack#resolve_stack!` early-returns whenever `pending_choices?` is true, regardless of which item is on top. This matters for any choice pushed synchronously by an `event_handlers`/`SpellCast` trigger at *cast* time (before `game.stack.resolve!` is ever called) — e.g. a "whenever you cast an instant or sorcery, copy/exile/etc." enchantment. The spell being cast can't resolve until that choice is resolved first, even though the choice logically "happens after" the spell in the card's own wording. In specs, resolve the choice(s) *before* calling `game.stack.resolve!`, not after — calling it first just silently no-ops (logs "pausing stack resolution") and nothing appears to have happened. Example: `ArcaneBombardment`.

**"Copy [a card in a non-stack zone, e.g. exile]. You may cast any number of the copies without paying their mana costs" (casting a *fresh* copy that never had targets, not retargeting an existing stack item)**: Different from the `Reiterate`/`CopyTargets` "may choose new targets" pattern — there `targets:` already exists (the original spell's chosen targets) and the choice only offers to *change* them. Here there's no existing target to inherit, so build a plain `Magic::Choice::Targeted` subclass that reads `@card.target_choices` fresh (same 0/1-arity check `Actions::Cast#target_choices` does) and calls `Magic::CopyEffect.resolve!(@card, targets: [target])` in `resolve!`; wrap it in a `Magic::Choice::May` whose `resolve!` pushes the targeted choice only if `choice.choices.any?` (falling back to `CopyEffect.resolve!(@card, targets: [])` directly for a copy that needs no target — same "if you can't" empty-pool guard used elsewhere), so "may cast" degrades gracefully for both targeted and targetless copies. For "any number of the copies" from an accumulating list (not a single spell), push one such `May` choice per card in the list — each is independently accept/decline, which is what "any number" means operationally. Example: `ArcaneBombardment` (also demonstrates the once-per-turn "first instant or sorcery spell" gate combined with an accumulating `exiled_cards` list read fresh — and re-copied in full — on every qualifying trigger).

**"Deals N damage divided as you choose among one or two targets" (fixed-amount divided damage, no cast-time targeting)**: Don't use `Actions::Cast`'s normal `target_choices`/`targeting` — there's no "1 or 2 of the same pool, arbitrary split" shape in the existing 0/1-arity single-target or fixed-list `multi_target?` mechanisms. Instead, skip `target_choices` on the card entirely and, from `resolve!`, push a plain `Magic::Choice` subclass (mirrors `NumaJoragaChieftain::DistributeCountersChoice`, minus the `amount:`/mana-payment wrapper): `choices` returns `game.any_target`, `resolve!(distribution:)` iterates a `{target => damage}` hash calling `trigger_effect(:deal_damage, target:, damage:)` per entry. Nothing validates the distribution sums to the spell's total or is capped at 1-2 targets — same unenforced-payment looseness as counter distribution elsewhere in this file; trust the caller (and the spec). Example: `ChandrasPyrohelix`.

**"Whenever an ability of equipped/attached creature is activated, if it isn't a mana ability, you may pay {N}. If you do, copy that ability. You may choose new targets for the copy."**: Wire a plain `TriggeredAbility` on `Events::AbilityActivated` (fired for mana abilities too, via `Actions::ActivateManaAbility`, so filter with `!event.ability.is_a?(Magic::ManaAbility)`) checking `event.ability.source == actor.attached_to` (`attached_to` comes from `Permanents::Enchantment`, mixed into every `Permanent` including Equipment — no Aura-specific plumbing needed). `call` pushes a `Magic::Choice::May` subclass (`resolve!(payment: {})` calls `controller.pay_mana(payment)` then `Magic::CopyEffect.resolve_with_choice!(actor:, receiver: event.ability, targets: event.targets)`) — `resolve_with_choice!` itself handles the "you may choose new targets" half by queuing a second choice when the copied ability had targets, so no extra plumbing needed for that clause. In specs, this pending choice is pushed synchronously at activation time (before the ability itself resolves), so per the "a pending choice blocks all stack resolution" note above: resolve the choice(s) *first*, then call `game.stack.resolve!` for the original ability — this also matches real timing, since the copy (a triggered ability) goes on the stack above the activated ability and resolves first. Example: `BattlemagesBracers`.
