# Cost Patterns

Activation/casting costs — sacrifice, kicker, discard, exile-self, alternative costs, mana production. Part of the card-implementation pattern catalog — see `docs/card_patterns.md` for the index.

**Activated ability with sacrifice cost**: Use `costs "{1}, Sacrifice {this}"` string. Define `single_target? = true`, `target_choices`, and `resolve!(target:)`. Example: `ThrashingBrontodon`.

**String mana cost format**: `cost "{2}{R}{G}"` is valid alongside the hash format `cost generic: 2, red: 1, green: 1`. Use string format when mixing more than two colors or for readability.

**"Tap N untapped [creatures matching X] you control" as an activated ability cost**: Use `Costs::MultiTap.new(predicate_lambda, n)` (`lib/magic/costs/multi_tap.rb`) — note the class does **not** itself enforce the count or the predicate (its `pay` just taps whatever permanents it's given, and its `can_pay?` references an undefined `permanent` method — don't call `can_be_activated?`/`can_pay?` on an ability with this cost). The predicate is documentation of intent for callers/specs, not validation. Pay it via `Actions::ActivateAbility#pay_multi_tap(permanents)` in specs. Example: `Shacklegeist`, `LathrilBladeOfTheElves`, `VoiceOfTheWoods`.

**Kicker paid with a non-mana cost (e.g. "Kicker—Sacrifice a creature")**: `kicker_cost` normally returns a `Costs::Kicker < Costs::Mana`, set via the `kicker_cost(cost)` DSL macro — mana-only. For a non-mana kicker, skip that macro and override the `kicker_cost` reader in the card's class reopening to lazily build a small duck-typed cost object instead (`.pay(player:, payment:)` + `.paid?`) — e.g. `Costs::SacrificeKicker`, which sacrifices `payment` and flips a `paid?` flag. `Actions::Cast#pay_kicker`/`#resolve!` (`kicked: kicker_cost.paid?`) don't care which class it is. Spec calls it the same way as a mana kicker: `a.pay_kicker(creature_permanent)`. Example: `PrimalGrowth`.

**Kicker on a non-permanent spell (instant/sorcery)**: `actor.kicked?` only works for permanents (the flag is baked into the `Permanent` at resolution). For a spell that never becomes a permanent, check `kicker_cost.paid?` directly on the card instead — the same card instance persists from cast through resolution, so `kicker_cost` (set during `pay_kicker`) is still valid inside `resolve!`. Example: `VastwoodSurge`.

**`LoyaltyAbility#resolve!`/`ActivatedAbility#resolve!` bodies must use `source`/`controller`/`trigger_effect`/`hand`/`graveyard`/`library`, not `actor`** — `Magic::Ability` (the base class both inherit from) defines exactly those delegators and has no `actor` method; calling `actor.trigger_effect(...)` inside a loyalty ability's `resolve!` raises `NoMethodError` at activation time. This is easy to miss because `Magic::Choice` subclasses *do* have `actor` (a different base class), so the two easily get confused. A card with no spec can hide this indefinitely since the bug only surfaces when the ability is actually activated.

**"{N}, {T}, Exile this [permanent]: ..." (exiling itself as an activation cost)**: `Costs::Parser` had no exile-self cost until `Costs::SelfExile` (mirrors `Costs::SelfSacrifice`) plus a `/Exile {this}/` case in the parser — write it as `costs "{3}, {T}, Exile {this}"` same as any other multi-part cost string. `Permanent#exile!` (mirrors `destroy!`) moves both the permanent and its underlying card to `game.exile`. `Player#activate_ability` auto-pays it unconditionally once present, same as `SelfTap`/`SelfSacrifice` — no explicit `pay_self_exile` call needed in specs. Example: `PlazaOfHeroes`.

**"Add one mana of any color. Spend this mana only to cast a legendary spell" (or similar restricted-use mana)**: There's no mana-pool tagging for *what a mana can be spent on* — `Player#mana_pool` is a flat `color => count` hash. Implement the production side only (`Magic::ManaAbility` with `choices :all`, or a computed `choices` list) and don't try to enforce the spending restriction; this matches the codebase's existing looseness around unenforced cost/payment rules (see kicker/counter-distribution notes above). Example: `PlazaOfHeroes`.

**A plain "Add N mana" spell (e.g. a Dark-Ritual-shaped sorcery)**: Write it as a raw `class CardName < Sorcery; card_name "..."; cost ...; def resolve! = controller.add_mana(red: n); end` (no DSL block, since `resolve!` needs to be a real method) — `controller.add_mana(color: n)` is the same direct `Player#add_mana` mutation `Sol Ring`/`ManaAbility` already use, not routed through `trigger_effect`. Example: `IrencragFeat`.

**"If you control a commander, you may cast this spell without paying its mana cost"**: No alternative-cost engine mechanism exists (or is needed) for this — `Actions::Cast#mana_cost=` is already a public setter (used by the Rebound free-recast pattern above), so a spec/caller can simply do `action.mana_cost = {}` before casting; `Costs::Mana.new({})` is `zero?`/always payable, so `can_perform?`/`perform` need no payment. Matches this codebase's general looseness around unenforced cost conditions (kicker restrictions, restricted-use mana) — nothing checks `player.commander` before allowing the empty-cost cast; the card doesn't need any method for this at all. `Player#commander`/`Player#add_commander` (`lib/magic/player.rb`) already exist from `CommandTower`. Example: `DeflectingSwat`.

**"{cost}, {T}, Discard a card: ..." (discard as part of an activated ability's cost)**: `Costs::Discard` already existed but `Costs::Parser` had no string case for it — added `/Discard a card/ => Discard.new(source.controller)` alongside the other cost-string cases. Write the cost as `costs "{R}, {T}, Discard a card"`; pay it in specs with `action.pay_discard(card)` (already wired generically in `Actions::ActivateAbility#pay`), same as the mana-ability discard costs already used it via a different path. Example: `JaxisTheTroublemaker`.

**Flashback (or kicker) paid with a non-mana cost, e.g. "Flashback—Sacrifice a Mountain"**: Mirrors the existing non-mana-kicker pattern (`Costs::SacrificeKicker`, `PrimalGrowth`) but for `flashback_cost` instead — override the `flashback_cost` reader directly on the card's class reopening (skip the `flashback(cost)` DSL macro, which stores a single shared `Costs::Mana` object reused — and, worse, balance-mutated — across every cast; see the Blitz note above for why that's unsafe for any non-trivially-reused cost) so a fresh cost object is built on every read. `Costs::SacrificeAlternativeCost` (`lib/magic/costs/sacrifice_alternative_cost.rb`) is a small reusable duck-typed stand-in for `Costs::Mana` — implements `zero?` (always `false`), `can_pay?(player)` (`player.lands.select(&predicate).any?` — generalize past `.lands` if some future card's predicate isn't land-shaped), `pay(player:, payment:)` (validates `predicate.call(payment) && payment.controller == player`, then `payment.sacrifice!`), `finalize!` (no-op), `paid?`, and `x` (`nil`) — the last two exist purely because `Actions::Cast#mana_cost`/`#resolve!` unconditionally read `cost.x` and (for kicker) `kicker_cost.paid?` regardless of cost type. Pay it through the *existing* `action.pay_mana(payment)` entry point — no engine changes needed — passing the permanent to sacrifice directly as `payment` instead of a mana hash; `pay_mana`'s `any_color_for_any_cost?` codepath is harmless here since it only calls `mana_cost.treat_any_color_as_any!` when a matching static ability is on the battlefield, which a non-mana cost object will never need to define. Example: `LavaDart` (predicate `->(permanent) { permanent.type?("Mountain") }`).

**Buyback** ("You may pay an additional {N} as you cast this spell. If you do, put this card into your hand as it resolves."): Reuses the existing kicker plumbing rather than inventing a new one — write `kicker_cost generic: N` plus the new `buyback` DSL macro (`Card.buyback`, defines `buyback?` to return `true`) on the card. `Actions::Cast#resolve!`'s existing flashback/rebound zone-move chain gained one more `elsif card.buyback? && kicker_cost.paid?` branch (checked before the plain `move_to_graveyard!` fallback) that calls `card.move_to_hand!(player)` instead. Pay it in specs with the ordinary `action.pay_kicker(generic: { ... })` — no new payment method needed. Example: `Reiterate`.

**"As an additional cost to cast this spell, discard two cards" (a multi-card additional cost, unlike the single-card `Costs::Discard` used for activated-ability costs)**: `Costs::Discard#pay` only ever takes one card as `payment`, so it can't express "discard N cards" as one additional cost. Added `Costs::DiscardCards.new(player, count)` (`pay(payment:)` takes an Array and raises unless `payment.size == count`) plus `Actions::Cast#pay_discard(payment)` (mirrors `#pay_sacrifice`: dispatches on whether `payment` is an Array — an Array pays the `Costs::DiscardCards` in `additional_costs`, a single card pays a plain `Costs::Discard` — tracks whichever cost was paid in `@paid_additional_costs`). Write the card the same way as `VillageRites`/`Harrow` — a plain `class CardName < Sorcery; card_name "..."; cost ...; def additional_costs = [Costs::DiscardCards.new(controller, 2)]; end` (no DSL block, since `additional_costs` needs to be a real method) — and pay it in specs with `action.pay_discard([card1, card2])`, same timing as `pay_sacrifice` (paid immediately at cast, not gated on stack resolution). Example: `CatharticReunion`.

**"As an additional cost to cast this spell, discard a card" (single-card version of the above)**: Use the plain `Costs::Discard` class directly — `additional_costs = [Costs::Discard.new(controller)]` — and pay it in specs with `action.pay_discard(card)` (a bare `Card`, not an Array); the same `Actions::Cast#pay_discard` dispatches to `Costs::Discard` for a non-Array argument. Example: `UnexpectedWindfall`.

**The `equip [Costs::Mana.new(...)]` DSL macro shares one `Costs::Mana` instance across every activation, forever**: `Cards::Equipment.equip(equip_cost)` closes over whatever cost object is passed at class-definition time and returns that same object from every `costs` call — fine for a spec that equips once, but a `Costs::Mana`'s `balance` is mutated in place by `pay`/`finalize!` and never reset, so a second equip activation anywhere in the same process (e.g. a second `it` block) overpays into an already-zeroed balance and raises `Overpayment`. Same root cause as `blitz_cost`/`adventure_cost` (documented above) — the fix is the same: don't use the macro, define the equip ability's own `costs` method to build a fresh `Costs::Mana.new(...)` on every call (`ActivateAbility#initialize` only reads `ability.costs` once per activation, so a fresh object per call is safe, just not a fresh object per *use* of the ability class). Example: `BattlemagesBracers::EquipAbility`.

**"You may play that card for as long as it remains exiled, and you may spend mana as though it were mana of any color to cast it" (an opponent's card exiled by your permanent)**: Track the card on the permanent (`actor.exiled_cards << card; card.exile!`), then return one `Abilities::Static::AnyColorForAnyCost` subclass that also defines `permits_casting_from_exile?(card)` (which `Action#in_permitted_zone?` reads, for lands too) and `any_color_for?(card)` — both `@source.exiled_cards.include?(card)`. `AnyColorForAnyCost#any_color_for?` defaults to `true` (Chromatic-Orrery-style "all your spells"); `Actions::Cast#pay_mana` now asks it per card, so the any-colour payment applies only to the exiled cards. `Actions::Cast#resolve!` passes `controller: player` through `resolve_with_args`, so a card you cast but don't own enters under your control (`Card#resolve!(controller:)` → `Permanent.resolve`). Example: `CunningRhetoric` (attack trigger checks `event.active_player != controller` and that some `attack.target` is you or a planeswalker you control).
