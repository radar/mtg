# Cross-Cutting Mechanics

Whole named mechanics spanning trigger+cost+static (Monarch, Ring tempts, Blitz, Adventure, Storm-adjacent, additional combat). Part of the card-implementation pattern catalog — see `docs/card_patterns.md` for the index.

**Monarch**: Implemented as a real cross-cutting game mechanic, not a per-card flag. `Game#monarch` / `Game#make_monarch!(player)` (notifies `Events::PlayerBecameMonarch`); `Player#monarch?` / `Player#become_monarch!`. `Game` subscribes to its own events (`subscribe(self)` in `initialize`) and its `receive_event` handles the two game-rule effects that aren't tied to any specific card: the monarch draws a card at the beginning of their own end step (`Events::BeginningOfEndStep`, compares `event.active_player`), and a creature dealing combat damage to the monarch transfers the monarchy to that creature's controller (`Events::CombatDamageDealt`, checks `event.target == monarch`). A card that grants monarch status (e.g. "you become the monarch" on ETB) only needs to call `actor.controller.become_monarch!` — the draw-each-end-step and combat-damage-transfer rules apply automatically regardless of which card granted it. Example: `CourtOfBounty`; mechanic tests live in `spec/game_spec.rb` rather than a card spec.

**"The Ring tempts you"** (LOTR "Ring-bearer" mechanic): Implemented as a real cross-cutting game mechanic, like Monarch above, not a per-card flag — only the "gain an emblem, level it up, choose a Ring-bearer" state machine is built so far, not the four abilities the emblem's levels grant (see below). `Game#the_ring_tempts!(player)` finds or creates that player's `Emblem::TheRing` (via `Game#ring_emblem_for(player)`, `emblems.find { it.is_a?(Emblem::TheRing) && it.owner == player }` — emblems dedupe per player, unlike a plain `game.add_emblem(Emblem.new(...))` which always adds a fresh one), calls `emblem.gain_next_ability!` (bumps `level`, capped at `Emblem::TheRing::MAX_LEVEL = 4`), notifies `Events::TheRingTemptsPlayer`, then — mandatory, not a `Choice::May`, matching the Oracle wording "you must choose a creature if you control one" — adds a `Choice::RingBearer.new(player:)` only if `player.creatures.any?` (the usual "if you can't" empty-pool guard). `Choice::RingBearer < Magic::Choice::Targeted` overrides `controller` to return the explicit `player:` ivar rather than the usual `actor.controller` (same reason as `RuthlessWinnower`'s edict choice: `actor` here is the `Player`, not a permanent/card, so there's no natural `.controller` to delegate to), and its `resolve!(target:)` clears the old `Permanent#ring_bearer` flag, sets the new one, and updates `Player#ring_bearer` (both plain `attr_accessor`s, mirroring `chosen_creature_type`). A card that triggers a tempt (e.g. "when this enters, the Ring tempts you") only needs `game.the_ring_tempts!(actor.controller)` from a simple ETB block. **Not yet implemented**: the four Ring abilities' actual effects (Ring-bearer is legendary and can't be blocked by greater power; draw-then-discard on Ring-bearer attack; Ring-bearer's blocker sacrifices itself at end of combat; Ring-bearer combat damage to a player drains each opponent for 3) — `Emblem::TheRing#level` tracks how many the player has, but nothing reads it yet. Add those as they're needed by a card that actually depends on them, the same way `Abilities::Static::*` classes get added on demand. Example: `FieryInscription`.

**"You may cast instant and sorcery spells from your graveyard. If a spell cast this way would be put into your graveyard, exile it instead."** (Jaya Ballard-style graveyard-casting emblem): `Magic::Emblem` gained two default-`false` hooks, `permits_casting_from_graveyard?(card)` and `exiles_after_graveyard_cast?(card)`, mirroring the `permits_casting_from_exile?`/`permits_casting_from_top?` hooks `Abilities::Static::*` classes already expose — `Actions::Cast#can_perform?` ORs in a `from_graveyard` check (`card.zone&.graveyard? && game.emblems.any? { |e| e.owner == player && e.respond_to?(:permits_casting_from_graveyard?) && e.permits_casting_from_graveyard?(card) }`), and `#resolve!`'s sorcery/instant zone-move branch checks the same emblems for `exiles_after_graveyard_cast?` before falling through to the normal `card.move_to_graveyard!` — same `card.zone&.graveyard?` guard (not `.graveyard?` unguarded: by the time `resolve!`'s zone-move branch runs, `card.zone` is `nil` for an ordinary hand-cast spell, so the unguarded call raises `NoMethodError` for every other spell in the suite). No mana-cost special-casing needed — `@flashback` stays `false` for this path, so `mana_cost` already falls through to the card's normal `cost`. A card's own emblem subclass only needs to override the two hooks (`card.instant? || card.sorcery?` for the permission, unconditional `true` for the exile). As with the cast-count-limit note above, `can_perform?` is advisory only — the actual cast in a spec just builds/pays/resolves a `Cast` action directly, same as any other spell. Example: `JayaBallard`.

**"You can cast only one more spell this turn" (or any other turn-scoped cast-count restriction)**: Unlike most cost/targeting restrictions in this file, this one is actually enforced — `Actions::Cast#can_perform?` is never consulted by `perform`/`take_action` (see `Ephemerate`/`DeflectingSwat` notes), so the check has to live in `perform` itself. `Player` has `limit_spells_this_turn!(n)` (sets `spell_cast_limit` + stamps `spell_cast_limit_turn = game.current_turn.number`, the same turn-number-stamp pattern as `SerpentsSoulJar`'s `exile_cast_permission_turn` — naturally expires once the turn advances, no cleanup step needed), `spell_cast_limited?` (true only while that stamp matches the current turn), `spell_cast_limit_reached?` (limited and count is `0`), and `consume_spell_cast!` (decrements, no-op when not limited). `Actions::Cast#perform` raises `Actions::Cast::SpellCastLimitReached` up front — before additional costs or mana are paid — if `player.spell_cast_limit_reached?`, then calls `player.consume_spell_cast!` right after `mana_cost.finalize!(player)` so every successful cast (not just the first) counts against the limit. A card sets it from its own `resolve!` (`controller.limit_spells_this_turn!(1)`) — the card's own cast already happened before `resolve!` runs, so the count only ever covers casts *after* it. Example: `IrencragFeat`.

**Blitz** ("You may cast this spell for its blitz cost. If you do, it gains haste and 'When this creature dies, draw a card.' Sacrifice it at the beginning of the next end step."): Implemented generically, mirroring `flashback`/`rebound`. `Card.blitz(cost)` DSL macro stores the raw cost hash as a `BLITZ_COST` constant (`const_set`, same shape as the plain `cost(cost)` macro) — **don't** pass a pre-built `Costs::Mana` instance like `flashback` does; `Card#blitz_cost` (base implementation) builds a *fresh* `Costs::Mana.new(self.class::BLITZ_COST.dup)` on every call. This matters because `Costs::Mana#dup` is a shallow copy — the duped object still aliases the original's `@balance` Hash, so paying down a `Costs::Mana` singleton shared across casts (as `flashback`'s `cost`-object-literal pattern does) permanently mutates that shared balance and the next cast to reuse it raises a bogus `Overpayment`. Building the cost fresh from a plain Hash each time sidesteps this. `Actions::Cast` takes a `blitz:` boolean (alongside `flashback:`); its memoized `mana_cost` reads `card.blitz_cost` when `@blitz`, and `resolve!` — after the card resolves as a permanent — calls `grant_haste!` and registers `Magic::Blitz::DeathDrawTrigger` (`Events::CreatureDied`, guarded by `this?`) and `Magic::Blitz::EndStepSacrificeTrigger` (`Events::BeginningOfEndStep`, unconditional `actor.sacrifice!`) via `register_turn_trigger` — both live in `lib/magic/blitz/` as small reusable `TriggeredAbility` subclasses. Drive it in specs with `player.cast(card:, blitz: true) { |a| a.pay_mana(...) }` (paying `card.blitz_cost`'s mana value, not the normal `cost`). The same two `Blitz::*Trigger` classes are reusable for any other "hasty, draws a card on death, sac'd at next end step" effect that isn't the blitz keyword itself — e.g. a token-copy ability with that exact wording — just `register_turn_trigger` them directly on the resulting permanent instead of duplicating card-local trigger classes. Example: `JaxisTheTroublemaker` (both the keyword and its activated ability use them).

**Adventure** (a card castable either as itself, or — earlier or later, from hand — as a differently-named/costed/typed spell that exiles instead of going to the graveyard, playable later as the "real" card from exile): No existing mechanism covered a second, fully independent cost/effect/type living on the same `Card` object, so this added generic `Actions::Cast` support rather than a card-local hack. `Card.adventure(cost)` DSL macro (mirrors `blitz`) stores `ADVENTURE_COST`; `Card#adventure_cost` (mirrors `blitz_cost`) builds a fresh `Costs::Mana` from it on every call, same shallow-`dup`-aliasing reason `blitz_cost` does. `Actions::Cast.new(..., adventure: true)` is a third alternate-cost flag alongside `flashback`/`blitz`: `mana_cost` reads `card.adventure_cost` instead of `card.cost`; `resolve!` calls `card.adventure_resolve!(...)` instead of `card.resolve!(...)` (via a new `method:` keyword on `ResolvesWithArgs#resolve_with_args`, so the same keyword-filtering logic works against either method name) and then unconditionally `card.exile!`s the card afterward regardless of the card's own type — this is what makes the *other* face playable later, since `Actions::PlayLand`/`Card#resolve!` have no zone restriction of their own (PlayLand just calls `card.resolve!`, `Player#cast`'s `can_perform?` isn't consulted by `perform`/`take_action`, only by specs). Define `adventure_resolve!` directly on the card class (separate from the type-line-driven `resolve!` used for the card's normal/permanent side — e.g. a land Adventure keeps `type T::Land, ...` and its default `resolve!` still makes a Permanent when played as a land, while `adventure_resolve!` is a distinct method for the spell-side effect, not a variant of `resolve!` gated by a flag). Drive it in specs with `player.cast(card:, adventure: true) { |a| a.pay_mana(...) }`, exactly like a normal cast. Example: `LindblumIndustrialRegency` (Land — Town front face; "Mage Siege" {2}{R} Instant — Adventure back face creates a 0/1 black Wizard token).

**Additional combat phase** (`game.current_turn.queue_additional_combat!` / `additional_combat_pending?` on `Game::Turn`, `lib/magic/game/turn.rb`): this state-machine plumbing already existed but had never been exercised by a card — the `second_main` event correctly transitions `end_of_combat: :beginning_of_combat` `if: :additional_combat_pending?`, but nothing ever decremented `@additional_combats`, so once *any* card queued one, every future `second_main!` for the rest of the game would keep re-triggering "one more" additional combat forever instead of exactly the number queued. Fixed by adding `after_transition from: :end_of_combat, to: :beginning_of_combat do |turn| turn.consume_additional_combat! end` (only fires on the transition actually gated by `additional_combat_pending?`) plus a `consume_additional_combat!` method decrementing the counter. No card needs to touch this directly — just call `queue_additional_combat!` once per extra combat phase the card grants (e.g. from an exert effect) and the state machine handles entering, then correctly not re-entering, the extra phase.

**`Actions::Cast#controller` is a dead reader — never actually assigned**: `Actions::Cast#initialize` accepts a `controller:` kwarg (default `card.controller`) but never stores it to `@controller`, so `attr_reader :controller` always returns `nil` for every `Actions::Cast` instance, including everything in `game.stack.spells`. Nothing else in the codebase reads it (every existing "spell you control" check reads `spell.card.controller` instead, e.g. `Reiterate`, `RinAndSeriInseperable`), so this has shipped silently broken. Don't call `.controller` on a stack item pulled from `game.stack.spells`/`game.stack.abilities` — use `.card.controller` instead. Discovered implementing `TwinningStaff`'s "target instant or sorcery spell you control."

**Proliferate** ("Choose any number of permanents and/or players, then give each another counter of each kind already there."): `Magic::Choice::Proliferate` (`lib/magic/choice/proliferate.rb`) is a plain `Magic::Choice`, not wrapped in `Choice::May` — "any number, including none" is expressed by defaulting `resolve!(chosen: [])` rather than by a separate accept/decline step. `choices` is `game.battlefield.select { |p| p.counters.any? } + game.players.select { |pl| pl.counters.any? }` (both `Permanent#counters` and `Player#counters` are populated `Counters::Collection`s already); `resolve!` groups each chosen entity's own counters by `.class` and calls `entity.add_counter(counter_class)` once per distinct class present — both `Permanent#add_counter` and `Player#add_counter` accept a counter *class* directly (`Counters.[]` special-cases `return counter_type if counter_type.is_a?(Class)`), so there's no need to map back to the string keys (`"+1/+1"`, etc.). A card just does `game.choices.add(Magic::Choice::Proliferate.new(actor: actor))` wherever its own trigger says "proliferate" — no per-card class needed. Example: `CacophonyScamp` (as the payoff for "you may sacrifice it. If you do, proliferate.").

**Cycling** ("{cost}, Discard this card: Draw a card."): No existing mechanism let a `Card` sitting in hand activate anything — `Card#activated_abilities` returns raw ability *classes* (only `Permanents::ContinuousEffects#calculate_activated_abililities` ever instantiates them, battlefield-only), so `FesteringThicket`'s land-cycling ability was dead code, only reachable (and only tested) once the land was already a permanent. Added a real hand-side path instead of reusing that: `Card.cycling(cost)` class macro (mirrors `blitz`/`adventure`) stores `CYCLING_COST`; `Card#cycling_cost` builds a fresh `Costs::Mana.new(self.class::CYCLING_COST.dup)` per call (same shallow-`dup`-aliasing reasoning as `blitz_cost`). `Actions::Cycle` (`lib/magic/actions/cycle.rb`) is a small standalone `Action` — no stack involvement needed, matching `Actions::PlayLand`'s directness — whose `perform` finalizes the mana cost, calls `card.discard!` (already existed, just previously unused for a self-inflicted cost), then `card.trigger_effect(:draw_cards, number_to_draw: 1)` (works after the discard since it's just metadata read off the `Card`, whose `controller` doesn't change on a zone move). Wired via `Player#cycle(card:) { |a| a.pay_mana(...) }`, mirroring `Player#play_land`. Card side is just the DSL macro plus `game.take_action` doesn't need touching. Example: `SparkSpray`.

**Hideaway N ("look at the top N cards, exile one face down, put the rest on the bottom in a random order") and "you may play the exiled card"**: An ETB trigger takes `controller.library.take(N)` and pushes a `Choice::Targeted` whose `choices` are those cards; `resolve!(target:)` does `target.exile!`, `actor.exiled_cards << target` (the permanent remembers it, like `GraspOfFate`), then removes the rest from the library and re-adds each with `library.add(card, library.count)` — **not** `library.count + index`, since `count` grows on every insert and the index then overshoots, padding the array with `nil`s (`NessianWanderer` still has that bug). The later payoff is a `Choice::May` whose `resolve!` does `actor.remove_from_exile(card)` then `controller.cast(card:, by_effect: true) { _1.mana_cost = 0 }`, the same free cast as `IdolOfEndurance`. Lands are skipped when the payoff is outside a main phase (a land can't be played then). Free-casting a spell that needs targets isn't handled. Example: `FightRigging`.

**"If that creature would die this turn, exile it instead"** (a replacement effect on one permanent that lapses at end of turn): `Permanent#register_turn_replacement(matcher, replacement_class)` adds a `[matcher, ReplacementEffect]` pair consulted by `replacement_effect_for` alongside the card's own `replacement_effects`, and is cleared in `Permanent#cleanup!` (the cleanup step; a spec needs `current_turn.end!` then `current_turn.cleanup!`, `game.next_turn` alone doesn't). `Magic::ReplacementEffect::ExileInsteadOfDying` is the reusable replacement (`MovePermanentZone` from the battlefield to a graveyard for that permanent becomes `Effects::ExilePermanent`); register it right after the damage: `target.register_turn_replacement(Magic::Effects::MovePermanentZone, Magic::ReplacementEffect::ExileInsteadOfDying)`. An exiled permanent's card is in `game.exile`, not `player.exile`: assert with `card.zone` `be_exile`. Example: `FeedTheFlames`.
