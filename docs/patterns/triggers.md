# Trigger Patterns

ETB / attack / upkeep / landfall / lifecycle / once-per-turn / delayed triggers. Part of the card-implementation pattern catalog — see `docs/card_patterns.md` for the index.

**Ward (additional life cost)**: Use `ward life: N` DSL in the card definition block. Automatically registers a `SpellCast` trigger that checks `opponents.include?(event.player) && event.targets.include?(actor)` and calls `trigger_effect(:lose_life, target: event.player, life: N)`. If the card also defines `event_handlers` in a class reopening, call `super.merge(...)` to preserve the ward trigger. Example: `TerrorOfThePeaks`.

**Simple ETB effect (no targeting/choice)**: Use the `enters_the_battlefield` DSL block inside the card definition — no class reopening needed. Example: `SetessanTraining` draws a card on ETB with `actor.trigger_effect(:draw_cards, number_to_draw: 1)`.

**"Check land" (as this land enters, you may reveal a [type] card from hand; if you don't, it enters tapped)**: `Card#resolve!`/`Permanent.resolve` read `enters_tapped?` synchronously *before* the permanent exists, so there's no window there for a player choice — don't try to gate `enters_tapped?` on a `revealed` flag set elsewhere (nothing will ever set it, and the land silently always enters tapped). Instead, make `enters_tapped? = true` unconditionally, then handle the reveal as a normal `etb_triggers` + `Magic::Choice::May`-wrapped `Magic::Choice::Targeted` (same "may" ETB pattern as above) whose `resolve!(target:)` calls `controller.reveal(target)` and `actor.untap!` — untapping just after entry is functionally identical to never having been tapped, since nothing gets priority in between. Guard the ETB trigger with the inner choice's `choices.any?` (the "if you can't" pattern) so no choice is offered — and the land stays tapped — when hand has no matching land. Example: `NecroblossomSnarl`, `ShineshadowSnarl`.

**ETB triggers**: Use `def etb_triggers = [TriggerClass]` (shorthand) instead of wiring via `event_handlers`. Both work, but `etb_triggers` is more explicit. Example: `AlpineHoundmaster`, `Trufflesnout`.

**Attack trigger (boost based on attacker count)**: Handle `Events::FinalAttackersDeclared` in `event_handlers`. Check `event.attacks.any? { |a| a.attacker == actor }` in `should_perform?`. Count other attackers with `event.attacks.reject { |a| a.attacker == actor }.count`. Apply via `trigger_effect(:modify_power_toughness, power: n, target: actor, until_eot: true)`. Example: `AlpineHoundmaster`.

**"At the beginning of enchanted player's upkeep" (or any trigger keyed to a specific attached player, not `you?`/controller)**: Plain `TriggeredAbility` (not `BeginningOfYourUpkeep`, which bakes in controller-equality) wired via `event_handlers` on `Events::BeginningOfUpkeep`, with `should_perform? = event.player == actor.attached_to`. "Deals damage to that player or a planeswalker that player controls" is a choice whose chooser is the ability's controller (the Curse's controller) by default MTG rules — `Magic::Choice`'s default `controller = actor.controller` already matches, no override needed (contrast `RuthlessWinnower`/`RingBearer`, where the chooser is a different player and `controller` has to be overridden). Build the option list as `[actor.attached_to, *game.battlefield.controlled_by(actor.attached_to).planeswalkers]` and push via `game.add_choice(...)` (not `game.choices.add`) so the common case — the enchanted player controls no planeswalkers, leaving exactly one legal target — auto-resolves per the single-target `Choice::Targeted` rule, and only queues a real choice once a planeswalker is in play. Example: `CurseOfThePiercedHeart`.

**"Nth event each turn" trigger (e.g. "second card drawn each turn")**: In a `TriggeredAbility#should_perform?`, count matching events from `game.current_turn.events` — events are tracked BEFORE listeners receive them, so the current event is included in the count. Example: `JolraelMwonvuliRecluse::SecondCardDrawTrigger` checks `current_turn.events.select { |e| e.is_a?(Events::CardDraw) && e.player == controller }.count == 2`. Caveat: `game.start!` draws 7 cards into the existing turn 1 event log, so testing fresh-turn triggers requires `2.times { game.next_turn }` to reach a clean turn.

**"Another nontoken Elf is put into your graveyard from the battlefield"**: Listen for `Events::LeftTheBattlefield`, not only `Events::CreatureDied` — Kindred Elves that are not creatures still count. Check `event.to.graveyard?`, `!event.permanent.token?`, `event.permanent.type?("Elf")`, and `event.permanent.controller == controller`. Wrap the token creation in `Magic::Choice::May`. Example: `ProwessOfTheFair`.

**"Whenever an Elf you control dies" (plain "dies" wording, unlike the "put into your graveyard" wording above)**: `Events::CreatureDied` is the right event here — "dies" means a *creature* going to the graveyard from the battlefield, so there's no non-creature-Kindred case to worry about (contrast with the `LeftTheBattlefield` case just above, which exists specifically because that wording also covers non-creature permanents). `event.controller` is already the dying permanent's controller (no `.permanent.controller` needed), so check `event.controller == controller && event.permanent.type?("Elf")` in `should_perform?`, wired via `event_handlers` (not `death_triggers` — the source enchantment itself never dies as an Elf, so the same-permanent restriction on lifecycle triggers would never fire). Example: `ElderfangVenom`, mirroring the unfiltered "any creature you control dies" trigger in `BastionOfRemembrance`.

**"Elves you control have '...'" (granting a triggered ability to a filtered set of permanents, including the source itself)**: There's no `Abilities::Static::GrantTriggeredAbilities` class yet — use `event_handlers` on the granting card (same as the "another Elf you control enters" pattern), since it dispatches for every permanent on the battlefield rather than only the source. Don't exclude `event.permanent == actor` — unlike "another Elf" wording, the source is itself one of the matching permanents and should be included. Example: `DionusElvishArchdruid` (`Events::PermanentTapped`, filtered to `event.permanent.type?("Elf") && event.permanent.controller == controller`).

**"Whenever this creature becomes tapped, untap it" (reacting to a permanent's own tap by immediately untapping it)**: `Permanent#tap!`/`#untap!` now flip `@tapped` *before* calling `game.notify!`, matching this codebase's general convention that a "such-and-such happened" event fires only after the state change is already applied (mirrors `Effects::MovePermanentZone` firing `PermanentEnteredZoneTransition` only after the zone move). This matters because triggered abilities in this engine run synchronously inside `notify!`, not via a queued/stack-based resolution — with the old tap-then-notify order, a handler calling `event.permanent.untap!` during `PermanentTapped` would have its change immediately clobbered when `tap!` unconditionally set `@tapped = true` right after `notify!` returned. If you ever see a trigger's state change to the event's own permanent seem to silently no-op, check this ordering first.

**"This ability triggers only once each turn" (per-permanent, not a global count)**: Don't reach for `game.current_turn.events` counting (that's for "Nth event each turn" triggers scoped to a player/controller, not to a specific permanent instance) and don't repurpose `mode_chosen_this_turn?`/`choose_mode_this_turn!` (that pair is specifically for Gala-Greeters-style modal "hasn't been chosen this turn" restrictions). Use the generic `permanent.triggered_once_this_turn?(key)` / `permanent.trigger_once_this_turn!(key)` pair on `Magic::Permanent` (reset in `cleanup!` alongside `modes_chosen_this_turn`) — key it on the triggered-ability class (`self.class`) so multiple distinct once-per-turn abilities on the same permanent don't collide. Example: `DionusElvishArchdruid::UntapAndGrowTrigger`.

**Lifecycle triggers (`etb_triggers`/`death_triggers`/`ltb_triggers`) only fire for the permanent's OWN entry/death/exit** — `Permanent#dispatch_lifecycle_triggers` early-returns unless `event.permanent == self`. For "whenever **another** Elf you control enters" (or any creature-enters/dies watching a *different* permanent), you must use `event_handlers` mapping `Events::EnteredTheBattlefield` (or `Events::LeftTheBattlefield`) to a `TriggeredAbility::EnterTheBattlefield` subclass instead — `dispatch_event_handlers` has no such same-permanent restriction and runs for every permanent on the battlefield. Mixing this up silently no-ops the trigger (no error, counters/tokens just never appear). Examples: `WatcherOfTheSpheres`, `DwynenGiltLeafDaen`, `MarwynTheNurturer`, `ElvishWarmaster`.

**"At the beginning of each upkeep" (not just yours)**: Don't use `TriggeredAbility::BeginningOfYourUpkeep` (that bakes in `you?`). Use a plain `TriggeredAbility` with no `should_perform?` override (or one that doesn't check the event's player) wired via `event_handlers` on `Events::BeginningOfUpkeep` — it fires for both players' upkeeps. Example: `WolverineRiders`.

**Rebound** ("If you cast this spell from your hand, exile it as it resolves. At the beginning of your next upkeep, you may cast this card from exile without paying its mana cost."): Use the `rebound` DSL macro (mirrors `flashback(cost)`, defines `rebound?` to return `true`) on the card. `Actions::Cast#resolve!` has a generic `elsif card.rebound? && card.zone.hand?` branch (alongside the existing `@flashback` branch) that exiles the card instead of moving it to the graveyard — `card.zone` never actually changes to a "stack" zone in this engine (it stays `hand`/`exile` throughout casting/resolution), so checking `card.zone.hand?` at resolution time reliably distinguishes "cast from hand" from "cast from exile via rebound" without a separate flag. `Zones::Exile` now subscribes/unsubscribes cards with `event_handlers` on add/remove, same as `Zones::Graveyard`/`Zones::Command` already did — this is what lets a card sitting in exile react to `Events::BeginningOfUpkeep` at all. Wire the delayed trigger as a plain card `event_handlers` entry (`Events::BeginningOfUpkeep => ReboundTrigger`, actor is the *card*, not a permanent — `Card#controller` exists so `TriggeredAbility::BeginningOfYourUpkeep`'s `you?` works unmodified) that pushes a `Magic::Choice::May` wrapping a `Magic::Choice::Targeted` for the optional recast (same two-step "may" pattern as `NecroblossomSnarl`). Since the card never leaves exile if declined, it would otherwise refire on every subsequent upkeep — this is a one-shot delayed trigger, not a recurring one, so guard `should_perform?` with an explicit `attr_accessor` flag on the card (e.g. `rebound_triggered`) set inside `call`, distinct from the "once per turn" `Permanent#triggered_once_this_turn?` helper (which resets every turn) and from zone-based unsubscription (which never happens here since the card doesn't move). For the free recast itself, build the action manually rather than via `player.cast`: `controller.prepare_cast(card: actor)` then `action.mana_cost = {}` (an empty-hash `Costs::Mana` is `zero?`/`can_pay?` true and needs no payment) then `action.targeting(target)` then `game.take_action(action)` — this still runs the real `Actions::Cast#perform` (so `Events::SpellCast` fires normally) followed by a normal `game.stack.resolve!`, and since `card.zone` is `exile` (not `hand`) at that point, the rebound branch above doesn't re-trigger and the card goes to the graveyard as usual afterward. Note `Actions::Cast#can_perform?` is never actually consulted by `perform`/`take_action` in this engine (only specs call it as an assertion) — no need to also thread a `permits_casting_from_exile?` static ability through for this to work. Example: `Ephemerate`.

**"Alliance — Whenever another creature you control enters, double this creature's power until end of turn"**: "Alliance" is just reminder text for "another creature you control enters," not a shared engine mechanic — wire it the same way as `DaxosBlessedByTheSun`'s "another creature enters" trigger: a `TriggeredAbility::EnterTheBattlefield` subclass checking `another_creature? && under_your_control?` (Daxos's own text has no controller restriction, so it omits the second check — don't crib that half), wired via `event_handlers` on `Events::EnteredTheBattlefield` (not `etb_triggers`, since this watches *other* permanents entering). "Double the power" is just `trigger_effect(:modify_power_toughness, power: actor.power, target: actor, until_eot: true)` — passing the creature's current power as the delta to add reproduces doubling, and naturally compounds correctly if it fires more than once in a turn since each firing reads the already-doubled power from the previous one. Like any `until_eot` modifier, the change only shows up in `permanent.power` after the next `game.tick!` — it isn't applied synchronously inside the trigger. Example: `DevilishValet`.

**"When you next cast an instant spell, cast a sorcery spell, or activate a loyalty ability this turn, ..." (a one-shot delayed trigger anchored to a spell that's about to leave play, not a permanent)**: `Magic::Permanent#register_turn_trigger` doesn't help here — the source is an Instant/Sorcery that moves to the graveyard the instant it finishes resolving, not a permanent that can `register_turn_trigger` on itself. The mechanism that *does* work: `Zones::Graveyard`/`Zones::Exile`/`Zones::Command` already `subscribe`/`unsubscribe` a card to `game`'s event listeners on add/remove whenever `card.event_handlers.any?` (this is also what makes Rebound's exile-side delayed trigger work) — so a plain Instant/Sorcery that defines `event_handlers` keeps receiving *every* game event for as long as it sits in the graveyard, same as any permanent. Guard firing yourself with a one-shot flag plus a turn-number check on the card instance (`@active_turn = game.current_turn.number` and `@used = false`, both set inside the card's own `resolve!` — before it moves to the graveyard — then a `pending?` reader checking `!@used && @active_turn == game.current_turn.number`): this bounds the trigger to "the rest of the turn it resolved in, and only once," matching "this turn" wording exactly, and there's no need to ever unsubscribe — after `pending?` goes false the handler is just an inert no-op for the rest of the card's life in the graveyard. For "cast a[n] {type} spell," use a `TriggeredAbility::SpellCast` subclass checking `you? && actor.pending? && (spell.instant? || spell.sorcery?)`; for "activate a loyalty ability" specifically (not any activated ability), use a plain `TriggeredAbility` on `Events::AbilityActivated` checking `you? && actor.pending? && event.ability.is_a?(Magic::LoyaltyAbility)` — both event classes can share the *same* one-shot flag on the card (`mark_used!` inside `call`) so only the first qualifying event of either kind fires, whichever comes first. Example: `RepeatedReverberation` (copies the qualifying spell/ability twice via `Magic::CopyEffect.resolve_with_choice!`, reading `event.spell`/`event.targets` or `event.ability`/`event.targets` straight off the event — no `Actions::Cast`/`Actions::ActivateAbility` object needed at all for this variant, unlike `Reiterate`'s stack-lookup version of the same copy mechanism).

**"Whenever a player casts a spell, if no mana was spent to cast that spell, ..."**: `Events::SpellCast` now carries `mana_cost:` (the `Actions::Cast#mana_cost` `Costs::Mana` object, passed in by `Actions::Cast#perform` at notify time), and `TriggeredAbility::SpellCast#mana_cost` delegates to `event.mana_cost` — a `TriggeredAbility::SpellCast` subclass just checks `mana_cost.zero?` directly, no need to look the casting action back up off `game.stack.spells`. `Costs::Mana#zero?` covers the real-world cases already implemented in this engine (a spell cast for `{0}` via `action.mana_cost = {}`, e.g. Rebound/commander-free-cast) — there's no tracking of "cost was nonzero but paid via non-mana," matching the codebase's general looseness around alternative-cost enforcement. Example: `RoilingVortex`.

**"Whenever you cast your first instant or sorcery spell each turn, ..."**: `TriggeredAbility::OncePerTurn` doesn't apply here — its gate reads `event.permanent`, which `Events::SpellCast` doesn't have. Gate manually instead, using the same underlying `Permanent#triggered_once_this_turn?`/`#trigger_once_this_turn!` pair (still reset in `cleanup!`): a `TriggeredAbility::SpellCast` subclass checks `you? && (spell.instant? || spell.sorcery?) && !actor.triggered_once_this_turn?(self.class)` in `should_perform?`, and calls `actor.trigger_once_this_turn!(self.class)` as the first line of `call` — `actor` is the permanent (an Enchantment/Artifact wired via `event_handlers`, not a lifecycle trigger, since this watches every cast in the game, not just the source's own entry). Example: `DoubleVision` (copies the spell via `Magic::CopyEffect.resolve_with_choice!`).

**Exert** ("You may exert it as it attacks. When you do, [effect]."): `Permanent#cannot_untap_next_turn!` (already existed, added for `SerpentsSoulJar`-adjacent effects) is exactly "won't untap during your next untap step" — no separate exert flag needed for that half. For "hasn't been exerted this turn," reuse the generic `Permanent#triggered_once_this_turn?`/`#trigger_once_this_turn!` pair keyed on the triggering ability's class, same as any other once-per-turn gate. Wire it as a plain `TriggeredAbility` on `Events::AttackDeclared` (fires once per attack, from `Turn#attackers_declared!`, carrying `event.attack.attacker`/`event.attack.target`) checking `event.attack.attacker == actor && !actor.triggered_once_this_turn?(self.class)`, whose `call` pushes a `Magic::Choice::May` subclass via `game.choices.add(...)` (not `game.add_choice` — a plain `May` isn't `Targeted`, and only `Targeted` choices get the single-legal-target auto-resolve special case, though `add_choice` also happens to work here since it no-ops for non-`Targeted` choices; `game.choices.add` is simply the established convention for a `May` with no target). The choice's `resolve!` (accept) does the actual mark-as-exerted (`actor.trigger_once_this_turn!(TheTriggerClass)`) plus whatever the effect grants; declining leaves the default no-op `May#decline!`. **The exerted creature itself stays tapped** — exert never untaps its own source, so a card built only around exert (no vigilance-granting or self-untap text) can't reattack in the additional combat phase with the same creature; that's expected, not a bug — other creatures need to carry the second attack. Example: `CombatCelebrant` (also untaps `other_creatures_you_control` and calls `game.current_turn.queue_additional_combat!`).

**Landfall + "exile the top card of your library, you may play it for as long as it remains exiled" (a recurring exile-then-play buffer, not a one-shot delayed trigger)**: `TriggeredAbility::Landfall` is an empty marker subclass — it has no built-in `should_perform?`, unlike `BeginningOfYourUpkeep`/`EnterTheBattlefield`. Wire it via `event_handlers` on `Events::Landfall` (fires for *any* player's land entering, `event.player` is that land's controller) and gate with the plain `you?` predicate yourself. Exile with the usual `actor.trigger_effect(:exile, target: card)` + `actor.exiled_cards << card` pair (`Permanent#exiled_cards`, see above). "You may play that card" needs **no** casting/playing permission static ability at all — `Actions::PlayLand#can_perform?` never checks the card's zone in the first place, and per the `Ephemerate` note above, `Actions::Cast#can_perform?`/`#perform` don't consult zone-permission hooks either; a spec just calls `player.play_land(land: exiled_card)` / `player.cast(card: exiled_card) { ... }` directly and it works regardless of which zone the card is sitting in. The "for as long as it remains exiled" clause is enforced implicitly, by the card simply no longer being in exile once something moves it out (here, the end-step cleanup below) — no expiration flag needed. For the "if there are cards exiled with this, put them in the graveyard, then deal that much damage" half: `TriggeredAbility::BeginningOfEndStep` + `controllers_end_step?`, gate `should_perform?` on `actor.exiled_cards.any?` (the usual empty-pool guard), snapshot `count = actor.exiled_cards.count` before mutating, then `actor.exiled_cards.each { |card| actor.remove_from_exile(card); card.move_to_graveyard!(card.owner) }` — safe to mutate `@exiled_cards` (via `remove_from_exile`) while iterating the list `each` was called on, since `Permanent#remove_from_exile` reassigns `@exiled_cards -= [card]` to a *new* array object rather than mutating the one already being enumerated. Example: `ValakutExploration`.
**"Whenever this creature is dealt damage, ..." (any damage, not just combat)**: `Events::DamageDealt` fires for both `Effects::DealDamage` and `Effects::DealCombatDamage` (the latter notifies `DamageDealt` with `combat: true` *and* `Events::CombatDamageDealt`), so a single plain `TriggeredAbility` on `Events::DamageDealt` checking `event.target == actor` catches noncombat damage (spells, fight, etc.) and combat damage alike — no need for two separate `event_handlers` entries. For "...it deals that much damage to target opponent," push a `Magic::Choice::Targeted` with `choices = actor.opponents` and `choice_amount = 1` via `game.add_choice(...)` (not `game.choices.add`) so a 2-player game's single legal opponent auto-resolves per the single-target rule. Example: `BrashTaunter`.

**"This creature fights another target creature"**: Don't reuse `Permanents::Creature#fight` — it's one-directional only (`source` deals damage to `target`, no damage back), which was fine for `PrimalMight`'s "creature gets +N/+N, then fights" wording (only the buffed side's damage is asserted there) but is wrong for a genuine mutual fight. Implement it directly in the activated ability's `resolve!` instead: `source.trigger_effect(:deal_damage, target: target, damage: source.power)` then `target.trigger_effect(:deal_damage, target: source, damage: target.power)` (call `trigger_effect` on each `Permanent` directly, not the ability's own `trigger_effect` shorthand, so each side is correctly attributed as its own damage source) — using `:deal_damage`, not `:deal_combat_damage`, since fight damage isn't combat damage (`Events::CombatDamageDealt` shouldn't fire, e.g. it must not transfer the Monarch). `target_choices` is `game.battlefield.creatures.except(source)` for "another target creature". Example: `BrashTaunter` (also demonstrates that a creature's own "whenever dealt damage" trigger correctly fires off the damage it takes from its own fight ability).

## TriggeredAbility Subclasses

Pre-built subclasses in `lib/magic/triggered_ability/` — use these to avoid rewriting `should_perform?`:

- `TriggeredAbility::BeginningOfYourUpkeep` — fires on `Events::BeginningOfUpkeep` only during controller's upkeep (`you?` built in)
- `TriggeredAbility::BeginningOfEndStep` — fires on `Events::BeginningOfEndStep`; provides `controllers_end_step?` helper
- `TriggeredAbility::EnterTheBattlefield` — provides `another_creature?`, `flying?`, `enchantment?`
- `TriggeredAbility::SpellCast` — provides `spell`, `enchantment?`
- `TriggeredAbility::Landfall`, `::Death`, `::LeaveTheBattlefield`, `::CounterAdded`, `::LoreCounterAdded`

**Composable `should_perform?` predicates on the base `TriggeredAbility` class** (`lib/magic/triggered_ability.rb`): prefer AND-chaining these named predicates over writing out the equivalent `event.permanent`/`game.current_turn` checks inline — `you?`, `opponent?`, `this?` (event permanent is the source), `type?`/`creature?`/`under_your_control?` (all check `event.permanent`), `controllers_turn?`. A second group assumes the event carries a spell as `event.source`/`event.target` instead (shape of `Events::DamageDealt`, fired by `Effects::DealDamage`): `instant?`/`sorcery?` (`event.source.instant?`/`event.source.sorcery?` — call both, AND'd, to check "instant or sorcery spell"; no `is_a?(Card)` guard, so only use these where `event.source` is known to be a spell, not a creature dealing combat/fight damage), `single_target_spell?` (`!card.multi_target?`, guarded with `respond_to?` since only multi-target cards define it), `spell_controlled_by_you?` (`event.source.controller == controller`), `damage_target_creature?` (`event.target.is_a?(Permanent) && event.target.creature?`, guards against `event.target` being a `Player`). Example: `ImodaneThePyrohammer` ("whenever an instant or sorcery spell you control that targets only a single creature deals damage to that creature, deal that much damage to each opponent"). `add_counter(counter_type, target: actor, amount: 1)` is a similar shorthand for `trigger_effect(:add_counter, counter_type:, target:, amount:)` — note this is a different method from `Permanent#add_counter`, which mutates counters directly with no event and must stay that way (it's what `Effects::AddCounterToPermanent#resolve!` itself calls; routing it back through `trigger_effect` would recurse).

**`Permanent#add_counter`/`#remove_counter` go through the effect pipeline, not raw mutation** — they call `trigger_effect(:add_counter, ...)`/`trigger_effect(:remove_counter, ...)` (`Effects::AddCounterToPermanent`/`Effects::RemoveCounterFromPermanent`, routed through `game.add_effect` and `ReplacementEffectResolver`), so any card calling `permanent.add_counter(...)`/`creature.remove_counter(...)` automatically gets `DoublingSeason`'s `CounterDoubler` (or any future counter replacement effect) applied — no card needs to reach for `trigger_effect(:add_counter, ...)` directly, and there is no longer a "wrong" raw path to accidentally call from card code. The actual mutation lives in `Permanent#put_counters!`/`#take_counters!` (bang, no event/replacement) — those exist only for `Effects::AddCounterToPermanent`/`RemoveCounterFromPermanent#resolve!` to call while resolving; card code should never call them directly. Originally found as a bug via `Aron, Benalia's Ruin`'s activated ability calling the raw path before this fix; combo tests: `spec/game/integration/aron_benalias_ruin_doubling_season_spec.rb`, `spec/game/integration/doubling_season_add_counter_spec.rb`.

**"Do this only once each turn" trigger** (e.g. "Whenever ~ becomes tapped, untap it... Do this only once each turn"): subclass `TriggeredAbility::OncePerTurn` instead of `TriggeredAbility` directly — its `perform!` override gates on and marks `Permanent#triggered_once_this_turn?`/`#trigger_once_this_turn!` (keyed on `self.class`) automatically, wrapping the real `should_perform?`/`call`. The card's own `should_perform?` only needs its domain conditions (the once-per-turn check is applied on top, outside the card's control) and `call` never has to remember to mark itself — there's no way to forget the bookkeeping since it isn't exposed to the subclass. Example: `DionusElvishArchdruid`.


**"If they entered or were cast from a graveyard"**: `Permanent#entered_from_graveyard?` (set in `Permanent.resolve` from the card's zone before it moves; a spell cast from a graveyard keeps its graveyard zone until it resolves; tokens/copies are nil). Gate an `Events::EnteredTheBattlefield` handler on it. The engine enters creatures one at a time, so "one or more" triggers fire per creature; for "only once each turn" on the *watcher*, `TriggeredAbility::OncePerTurn` doesn't fit (it keys on `event.permanent`) — mark `actor.trigger_once_this_turn!(self.class)` in `trigger!`. Example: `TwilightDiviner`.
